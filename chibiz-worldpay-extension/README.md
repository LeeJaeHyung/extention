# 차이비즈 월드페이 자동 결제 (크롬 익스텐션)

차이비즈 **새 관리자 웹**의 «1688 결제 대기» 화면에서 「결제 링크 받기」로 연 **1688 결제 페이지**에서만,
결제 수단 **월드페이(跨境宝 · `kjpayV2`)** 를 고르고 결제 버튼(立即付款)까지 눌러 주는 익스텐션입니다.
티켓 `new-chibiz/docs/agents/tickets/T-20261015-04` 의 구현본입니다. Manifest V3 · 빌드 없는 순수 JS.

## 🔴 안전 규칙 (반드시 읽기)

- **월드페이(`kjpayV2`) 밖의 결제 수단은 어떤 경우에도 누르지 않습니다** — 외상(先采后付 `shegou`)·알리페이(`alipay`)·跨境直采(`CROSS_BORDER_MYBANK`)·**조합결제(`combinationPay_*`)** 전부. 판정은 `src/core.js#isClickAllowed` 한 곳.
- **관리자 웹에서 연 결제 페이지에서만** 동작합니다. 1688 에서 직접 연 결제 페이지는 건드리지 않습니다.
  작동 조건(모두 통과해야 결제 버튼을 누름): 화면(묶음은 서버 모델) 주문번호 == 등록된 작업의 1688 주문번호 집합 · 월드페이 카드가 있고 쓸 수 있음(`avaliable:true`) · 월드페이가 묶음의 주문을 전부 덮음 · 결제 버튼 수단(`.operate-zone[data-channel]`)이 전부 `kjpayV2` · 통화가 人民币(CNY) · **주문 총액(`订单总金额`·서버 모델 `totalPayFee`)이 관리자 웹의 1688 금액과 分 단위로 정확히 같음.** 하나라도 아니면 **멈추고 경고 띠**를 띄우고 아무것도 누르지 않습니다.
- **어떤 입력칸(input·textarea)에도 값을 넣지 않습니다**(비밀번호 창은 아래 §비밀번호 단계).
- 월드페이 수단이 없거나 쓸 수 없으면 **멈추고 경고** — 다른 수단으로 넘어가지 않습니다.
- **1688 에 로그인되어 있지 않으면**(결제 페이지에 «Session过期») 경고만 띄우고 작업은 남깁니다(주계정 jungpan88 로그인 뒤 관리자 웹에서 링크 다시 받기 · 같은 탭에서 로그인 뒤 새로 고침하면 다시 판정).
- 작업은 **10분** 뒤 사라지고, 결제 버튼을 **한 번** 누르면 소각됩니다(새로 고침·뒤로 가기로 다시 누르지 않음).

## 설치 (관리자 PC)

1. 크롬 주소창에 `chrome://extensions` → 오른쪽 위 **«개발자 모드»** 켜기.
2. **«압축 해제된 확장 프로그램을 로드합니다»** → 이 폴더(`chibiz-worldpay-extension`)를 고릅니다.
3. 관리자 웹(`http://localhost:3001` · 운영 도메인은 아래 §설정)을 열면 「결제 링크 받기」 옆에 **«월드페이 자동 결제 켜짐»** 초록 표시가 보입니다. «익스텐션 없음» 이면 설치가 안 된 것입니다.
4. 코드를 고쳤으면 `chrome://extensions` 에서 이 익스텐션의 **새로 고침(↻)** 을 누르고, 열려 있던 관리자 웹·결제 페이지 탭도 새로 고칩니다.

## 사용

1. 관리자 웹 «1688 결제 대기» 에서 주문을 고르고 **「1688 동기화」로 1688 금액을 먼저 채웁니다**(금액을 모르는 주문이 있으면 자동 결제 작업을 보내지 않습니다).
2. **「결제 링크 받기」** 를 누르면 새 탭으로 1688 결제 페이지가 열리고, 익스텐션이 그 주문·금액에 맞는 작업을 받습니다.
   창에 «월드페이 자동 결제 작업 등록됨» 이 뜨면 등록된 것입니다.
3. 열린 결제 페이지에서 익스텐션이 월드페이를 고르고 결제 버튼까지 누릅니다(설정에 따라 다름 · 아래 §안전 스위치).
4. 결제 버튼 뒤 화면(비밀번호·인증)은 §비밀번호 단계를 보세요.

## 안전 스위치 (익스텐션 팝업)

- **«결제 버튼 자동 클릭»**(기본 **켜짐**) — 끄면 월드페이 선택·확인까지만 하고 «결제 버튼을 직접 누르세요» 띠를 띄웁니다.
- **«시험 모드(dry-run)»** — 결제 버튼 직전까지 모두 하고 «여기서 눌렀을 것» 만 띄웁니다. **결제 버튼은 누르지 않습니다.**
  🔴 개발·검증은 시험 모드로만 합니다. 실제 결제 클릭 검증은 사람이 직접 소액 주문으로.
- 팝업에서 **대기 중인 작업**과 **최근 결과**(브라우저를 닫으면 사라짐)를 볼 수 있습니다.

## 🆕 외상(先采后付) 결제 (0.6.0 · 2026-10-23 사용자 지시 «월드페이 최우선 · 실패·미지원이면 외상으로»)

- 🔴 **서버 작업이 `payChannel: "CREDIT"` 으로 지정했을 때만** 외상 카드(`shegou` · 先采后付 确认收货后付款)를 누릅니다. 관리자 웹 작업·월드페이 작업은 지금처럼 외상을 절대 누르지 않습니다(외상이 기본 선택이어도 월드페이로 바꿔 고름).
- 외상 작업도 같은 확인: 카드 선택 → 결제 버튼이 외상으로 잡혔는지(operate-zone) → 화면 금액 = 작업 금액 → 결제 버튼 1회 → 비밀번호(같은 알리페이 창 예상 · 실측 전).
- 카드의 «剩余额度 ¥…»(남은 한도)를 읽어 작업 금액보다 작으면 누르지 않고 `CREDIT_LIMIT_SHORT`.
- 알리페이·조합결제는 어떤 작업에서도 누르지 않습니다. «언제 외상으로 넘길지»(5분·실패 화면·월드페이 없음)는 서버가 1688 재조회 뒤 정합니다(T-20261015-05 §15).

## 🆕 결제 완료 감지 (0.5.0 · 2026-10-23 사용자 지시)

결제 버튼을 누른 탭에서 결제 완료 글자(支付成功·付款成功·交易成功 등 · `config.js#SUCCESS_DETECT.texts` · 🔴 실측 전 목록)를 지켜봅니다.
- 비밀번호 창(알리페이) 안 · 1688 결제 페이지 · 그 탭이 넘어간 1688 결과 페이지(`air.1688.com/*`·`trade.1688.com/*` 최상위 · 읽기만)
- 보이면 그 즉시 서버에 보고: code 끝 `:SUCCESS_SEEN` · 사유 «결제 완료 화면 감지(글자)» · 결제 페이지 띠 «결제 완료 화면을 감지했습니다»
- 못 보면(비밀번호 다음 뒤 60초 · 탭 닫힘 · 시한) code 끝 `:NO_SUCCESS_SEEN` + 사유에 «마지막 페이지 경로»(쿼리 없음) — 실제 완료 화면 주소를 배우는 용도
- 결제 버튼을 누른 지 15분 안의 신호만 받음 · 🔴 정본 판정은 언제나 서버의 1688 조회(`paidConfirmed`)

## 비밀번호 단계 (§4-5 · 🆕 0.4.0 시험 작업 자동 입력)

🆕 **0.4.0(2026-10-22 사용자 지시 «서버에 저장된 비밀번호를 받아 자동 기입»)** — 관리자 «월드페이 결제 시험» 작업(TEST)에만:

1. 관리자 웹 «결제 비밀번호 설정» 에 저장해 두면, 서버가 claim 응답에 **1회용 표**(`revealToken` · 10분)를 실어 줍니다.
2. 비밀번호 창이 우리 결제로 뜬 순간(아래 조건 그대로) background 가 표를 **먼저 지우고** `POST /order/worldpay-test/ext/payment-password/reveal` 를 1회 부름.
3. 받은 값은 그 프레임 응답으로만 건네고, 프레임은 칸에 넣은 뒤(브라우저 기본 setter + input/change) «下一步» 이 켜지면 **한 번** 누르고 값을 버립니다 → `AUTO_SUBMITTED`.
4. 칸이 없음·«下一步» 이 안 켜짐(보안 입력이 받지 않음) → 🔴 **우회하지 않고** 칸을 비운 뒤 «직접 입력해 주세요»(아래 0.3.0 흐름) · 틀림 문구 → `WRONG`(🔴 다시 넣지 않음).
5. 팝업 «비밀번호 자동 입력»(기본 켜짐)을 끄거나 · 표가 없거나 · 받기 실패 · 서버 자동 결제(SERVER) 작업이면 사람이 직접.

🔴 비밀번호 값은 저장소·콘솔·결과 목록·서버 보고 어디에도 남지 않습니다(단위 시험이 검사). 🔴 칸 선택자(`PASSWORD_STEP.inputSelectors`)는 **실측 전**입니다 — 못 찾으면 사람이 직접.

### 0.3.0 사람이 직접 입력(표가 없을 때 · 자동 입력이 안 될 때)

결제 버튼을 누르면 뜨는 알리페이 **«请输入支付宝密码»** 창은 1688 결제 페이지 안에 박힌 **교차 출처 iframe**(`https://pcauth-site.alipay.com/home`)입니다.

🆕 **0.3.0(W-1 · 2026-10-22 사용자 결정 «비밀번호는 사람이 그 순간 직접 입력»)**: 익스텐션은 이 창을 **알아보고 사람에게 넘기기만** 합니다 —
비밀번호를 받아 오거나 칸에 넣거나 «下一步» 을 누르지 않습니다. 창이 우리 결제로 뜬 것이면(상위가 air.1688.com · 이 탭에서 2분 안에 우리가 결제 버튼을 누름 · 제목 일치)
상위 결제 페이지에 **«비밀번호를 직접 입력해 주세요»** 띠를 띄우고, 사람이 «下一步» 을 누르는지만 **읽어서** 서버 작업에 보고합니다:

- `USER_SUBMITTED` — 사람이 비밀번호를 넣고 «下一步» 을 누름(그 뒤 틀림 문구가 뜨면 `WRONG`)
- `MANUAL_TIMEOUT` — 지켜보는 동안(추정값 5분) 누르지 않음

🔴 **입력칸의 값은 읽지 않습니다. iframe 주소의 쿼리(세션 값)도 읽지 않습니다.** 비밀번호에 관한 어떤 값도 받지·넣지·저장하지 않습니다.
옛 «서버에서 비밀번호를 받아 자동 입력(`PASSWORD_URL`·`/ex/ps`)» 경로는 0.3.0 에서 **없앴습니다**.

## 설정 (한 곳)

- **서버 주소**: `src/config.js` 맨 위 `const SERVER_BASE_URL`(기본 `https://lavender-untrimmed-sacred.ngrok-free.dev/dev-api`). 시험 작업·서버 자동 결제가 모두 이 주소를 씁니다.
  모든 요청에 `ngrok-skip-browser-warning: 1` 헤더가 붙습니다. 🔴 주소를 바꾸면 `manifest.json` 의 `host_permissions` 도 같은 출처로 바꾸세요.
- **익스텐션 키**: `config.js#TESTPAY.EXTENSION_KEY`(시험 작업 · 헤더 `X-WORLDPAY-TEST-KEY`) · `config.js#AUTOPAY.EXTENSION_KEY`(서버 자동 결제). 서버 값과 같아야 합니다.
- **관리자 웹 출처**: `manifest.json` 의 `content_scripts[0].matches` — 지금 `http://localhost:3001/*`(같은 브라우저 «결제 링크 받기» 흐름 T-04 용). 시험 작업(다른 PC)은 서버를 거치므로 이 매치가 없어도 됩니다.
- 시간·시한 등 다른 값은 `src/config.js`(전부 «추정한 값» 이라고 주석에 적음).

## 🆕 시험 작업 받기 (관리자 «월드페이 결제 시험» · 다른 PC · 0.3.0)

관리자가 **다른 PC 의 관리자 웹**에서 «월드페이 결제 시험» 으로 결제 작업을 만들면, 이 익스텐션이 서버에서 그 작업을 받아 결제 페이지를 엽니다.

1. 팝업에서 **«시험 작업 받기»** 를 켭니다(기본 꺼짐). 켜면 익스텐션이 일정 주기로 서버 `POST /order/worldpay-test/ext/claim`(키 헤더 `X-WORLDPAY-TEST-KEY`)를 부릅니다.
2. 작업을 받으면 `payUrl`(1688 결제 페이지)을 새 탭으로 열고, 관리자 웹 «결제 링크 받기» 흐름과 **똑같이** 월드페이를 고르고 결제 버튼을 누릅니다.
3. 결제 비밀번호 창에서는 **사람이 직접** 입력합니다(위 §비밀번호 단계).
4. 결과(제출됨·막힘·비밀번호 실패·로그인 만료·오류)를 서버 `POST /order/worldpay-test/ext/jobs/{jobId}/result` 로 보고합니다. 관리자 웹이 그 결과와 1688 결제 여부를 보여 줍니다.

🔴 **서버 자동 결제(«서버 작업 자동 실행» · T-20261015-05)와는 주소·키·스위치·멈춤 상태가 모두 따로**입니다(섞이지 않음). 둘 다 기본 꺼짐.

## 권한

- `storage`·`alarms` + `host_permissions` 는 **서버 출처 하나**(ngrok · 시험 작업·자동 결제 공용) + content script 매치 세 곳(관리자 웹 · 1688 결제 페이지 · 알리페이 비밀번호 창)뿐입니다. `<all_urls>`·`tabs`·`scripting` 같은 넓은 권한은 쓰지 않습니다.
